# CodeAlpha Cyber Security Internship - Task 3: Secure Coding Review

**Aegis Code Audit** is a full-stack **Static Application Security Testing (SAST)** platform and standalone Python CLI built for automated and manual secure code reviews against OWASP Top 10 and CWE security standards.

## What It Audits

- **Languages:** Python (real `ast.parse` taint tracking), JavaScript & TypeScript (real `@babel/parser` AST taint tracking + Regex fallback), PHP (SQLi, shell execution, `eval`, hardcoded secrets, `include`/`require` LFI), Go, and SQL.
- **Vulnerability Classes:** SQL Injection (`CWE-89`), OS Command Injection (`CWE-78`), Dynamic Code Execution (`CWE-95`), Insecure Deserialization (`CWE-502`), Hardcoded Secrets & High-Entropy Tokens (`CWE-798`), Weak Cryptography (`CWE-328`, `CWE-338`), XSS (`CWE-79`), TLS Misconfiguration (`CWE-295`), Debug Mode Exposure (`CWE-489`), and Path Traversal (`CWE-22`).
- **Supply-Chain Dependencies:** Live OSV.dev CVE lookups for `package.json`, `requirements.txt`, and `go.mod`.

## How the Audit Was Done

1. **Static Analysis (AST + Regex + Entropy):**
   - Python source files are parsed with `ast.parse` (`server/python_ast_auditor.py`, invoked via `child_process`, with automatic Regex fallback if `python3` is unavailable).
   - JavaScript and TypeScript files are parsed with `@babel/parser` (`src/utils/jsAstAnalyzer.ts`) to trace tainted inputs into dangerous sinks, falling back to Regex if parsing fails.
   - PHP, Go, SQL, and custom organization rules are evaluated deterministically alongside Shannon entropy credential detection.
   - Each finding reports its analysis engine (`AST` or `Regex`), CWE, OWASP Top 10 category, CVSS score, and taint flow.
2. **Manual Verification & Remediation:**
   - Findings are inspected alongside surrounding source context, triaged (`Open`, `Confirmed`, `Remediated`, `False Positive`) with auditor verification notes, and remediated using side-by-side secure patterns or server-side Gemini context-aware patching.
   - Results export as **Markdown** (`.md`) and **SARIF 2.1.0** (`.sarif.json`) reports.

## CLI Usage

The standalone Python CLI runs on plain Python 3 with zero third-party packages:

```bash
# Scan a file or project directory
python3 secure_code_auditor.py samples/vulnerable_app.py

# Scan and export a Markdown audit report
python3 secure_code_auditor.py samples/vulnerable_app.py --report AUDIT_REPORT.md
```

## Local Development

### 1. Prerequisites
- Node.js `v22+`
- Python `3.10+` (for Python AST analysis and standalone CLI)
- Google Cloud SDK (`gcloud` CLI) and Firebase CLI (for optional cloud deployment)

### 2. Environment Setup
Copy `.env.example` to `.env` and configure your runtime secret (never commit `.env`):
```bash
cp .env.example .env
```

Install dependencies and run unit tests:
```bash
npm install
npx --yes tsx --test src/utils/sastEngine.test.ts
```

Start the unified full-stack development server on port `3000`:
```bash
npm run dev
```

Build and run production server:
```bash
npm run build
npm start
```

## Security & Cloud Deployment Guide (Google Cloud Run)

### 1. Enable Required Google Cloud APIs
```bash
gcloud services enable \
  run.googleapis.com \
  secretmanager.googleapis.com \
  firestore.googleapis.com
```

### 2. Secret Manager Setup & IAM Bindings
Never hardcode API keys or credentials in source code. Store `GEMINI_API_KEY` in Google Cloud Secret Manager and grant the Cloud Run runtime service account access:

```bash
# Create and populate the secret
gcloud secrets create GEMINI_API_KEY --replication-policy="automatic"
echo -n "YOUR_API_KEY" | gcloud secrets versions add GEMINI_API_KEY --data-file=-

# Grant the default Cloud Run service account access to read the secret
gcloud secrets add-iam-policy-binding GEMINI_API_KEY \
  --member="serviceAccount:YOUR_PROJECT_NUMBER-compute@developer.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"
```

### 3. Firestore Security Configuration (Optional Multi-User Cloud Persistence)
If deploying with Firebase Auth and Cloud Firestore, enforce strict owner-bound document isolation in `firestore.rules`:

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/interactions/{interactionId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

Deploy rules via Firebase CLI:
```bash
firebase deploy --only firestore:rules
```

### 4. Deploy to Google Cloud Run
```bash
gcloud run deploy aegis-code-audit \
  --source . \
  --region us-central1 \
  --allow-unauthenticated \
  --set-secrets="GEMINI_API_KEY=GEMINI_API_KEY:latest"
```
